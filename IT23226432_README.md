## 📖 Executive Summary
Commercial hotel, resort, and athletic swimming pools consume massive amounts of electrical energy to maintain guest water comfort (typically between **33.0°C and 35.0°C**). Traditional commercial pool heaters (such as 30kW 3-phase heating units) rely on reactive, thermostat-only control logic. A standard thermostat continues burning grid electricity right up to the 35.0°C ceiling without accounting for incoming ambient solar heat gain—resulting in thermal overshoot, wasted kilowatt-hours (kWh), and inflated Ceylon Electricity Board (CEB) utility bills.

The **Algorithmic Energy Optimization System** is an intelligent, closed-loop cyber-physical system that replaces reactive thermostat control with **Predictive Thermal Coasting (Early Cut-Off)** and **20-Minute Hysteresis Segment Control**. By integrating:
1. **Dual-Sensor Edge IoT Telemetry (ESP32)** measuring real-time ambient air temperature, relative humidity (`DHT22`), and sub-surface pool water temperature (`DS18B20`) with local `U8g2` OLED status feedback,
2. **Machine Learning Thermal Forecasting (`ecopool_model.pkl`)** trained on 18,000+ thermodynamic telemetry rows to predict 20-minute environmental warming and passive pool heat transfer,
3. **Dynamic ML Stop-Point & 33.0°C–35.0°C Comfort Band Hysteresis (`optimizationController.js`)** that shuts off the heater early ($T_{\text{stop}} = 35.0^\circ\text{C} - \Delta T_{\text{20M}}$) so free natural solar heat carries the 65,000-liter water mass to 35.0°C, and keeps the heater locked OFF until the water cools below 33.0°C, and
4. **Real-Time CEB Financial ROI & 20-Minute Savings Ledger (`EnergyOptimizer.jsx`)** calculating avoided electrical load ($75.40\text{ kWh}/^\circ\text{C}$) and commercial CEB tariff savings ($\text{Rs. } 38.00/\text{kWh}$),

the component eliminates thermal overshoot, harvests passive solar energy, and delivers verifiable financial ROI for commercial aquatic facilities.

## 🚀 Key Features

### 1. Real-Time Dual-Sensor Edge Telemetry & OLED Feedback
- Ingests live environmental temperature and relative humidity from a **DHT22** sensor (Pin 23) and waterproof pool temperature from a **DS18B20** DallasTemperature sensor (Pin 4) on an ESP32 microcontroller.
- Features `WiFiMulti` automatic network failover between facility Wi-Fi (`SLT-Fiber-2.4G`) and mobile hotspot (`Galaxy M21A4BF`) for uninterrupted connectivity.
- Broadcasts JSON telemetry every 2 seconds over MQTT (`broker.hivemq.com:1883`) to topic `ecopool/umi/sensors`.
- Renders real-time water temperature and heater actuation state (`HEATER ON` / `HEATER OFF`) on a local 128x64 **SSD1306 I2C OLED Display** (`U8g2`) alongside physical Green/Red LED indicators and a 5V Relay contactor interface.

### 2. 20-Minute ML Thermal Forecasting & Dynamic Stop-Point Calculation
- Executes a serialized Python Machine Learning model (`ecopool_model.pkl` via `predict_temp.py`) trained on 18,000 rows of thermodynamic pool telemetry (`Ambient_Temp_C`, `Ambient_Humidity_Pct`, `Pool_Temp_C`, `Heater_Status`).
- Predicts the **Next 20-Minute Environment Temperature** (`predictedAmbientTemp20M`) and **20-Minute Natural Pool Heat Gain** (`naturalPoolHeatGain20M`).
- Dynamically computes the exact **ML Heater Stop Point**:
  $$\text{ML Stop Point} = 35.00^\circ\text{C} - \Delta T_{\text{natural (20M)}}$$
- Includes a thermodynamic realism guardrail for out-of-distribution manual test inputs (`< 28.0°C` or `> 35.5°C`).

### 3. 33.0°C – 35.0°C Hotel Comfort Band & Hysteresis Automation
- Enforces commercial hotel comfort standards (**33.0°C minimum** to **35.0°C maximum**) across automated 20-minute (`1200s`) evaluation segments:
  - **Active Heating Phase:** Keeps the 30kW heater ON while water temperature climbs toward the dynamic `ML Stop Point`.
  - **Early Cut-Off & Standby Lock (`isWaitingFor33Drop`):** The moment live pool temperature reaches the `ML Stop Point` (or `35.0°C`), the backend dispatches an MQTT `"OFF"` command to `ecopool/umi/control`, flipping the ESP32 relay OFF and engaging Comfort Standby Mode.
  - **Cooldown Hysteresis:** Prevents short-cycling by keeping the heater locked OFF across subsequent 20-minute checks as long as the pool remains between `33.0°C` and `35.0°C`.
  - **Low-Temperature (`< 33.0°C`) Alert & Re-Heat Trigger:** Automatically triggers a high-priority dashboard alert popup if water temperature drops below `33.0°C`, allowing instant or automated re-activation of the heating cycle.

### 4. Commercial CEB Financial ROI Engine & 20-Minute Savings Ledger
- Quantifies exact thermodynamic energy savings for a **65,000-liter** commercial pool using the specific heat capacity of water ($0.00116\text{ kWh/L/}^\circ\text{C}$):
  - **Energy per $1.0^\circ\text{C}$:** $65,000\text{ L} \times 0.00116 = 75.40\text{ kWh}$ ($7.54\text{ kWh}$ per $0.1^\circ\text{C}$).
  - **Commercial CEB Tariff Valuation:** Calculated at $\text{Rs. } 38.00/\text{kWh}$ ($\text{Rs. } 286.52$ saved per $0.1^\circ\text{C}$ of natural solar heating).
- Logs every verified 20-minute saving segment into a persistent **20-Min Savings Log** tab with duplicate-prevention locks and cumulative kWh and LKR totals.

### 5. Dual Operational Modes & Bi-Directional Hardware Override
- **Live Hardware Mode:** Streams real-time ESP32 telemetry every 1 second and executes automated ML cycles every 20 minutes after initial manager activation.
- **Manual Demo Mode:** Provides interactive override inputs for sensor values and 20-minute forecast parameters, plus a 1-click `Demo Stop @ [ML Stop Point]°C` trigger and bottom-docked manual hardware override buttons (`Force ON`, `Force OFF`, `Auto Mode`).

## 🧮 Thermodynamic & Financial Data Schema

The component processes real-time telemetry, ML inference payloads, and 20-minute savings records using the following data structures:

| Data Entity / Storage | Description | Key Attributes |
|---|---|---|
| `ecopool/umi/sensors` (MQTT) | Real-time JSON telemetry published by ESP32 every 2s | `ambientTemp` (°C), `humidity` (%), `currentPoolTemp` (°C) |

```env
CEB_COMMERCIAL_RATE_LKR=38.0
MAX_POOL_TEMP=35.0

```

### 2. ESP32 Hardware Pinout Matrix

| Hardware Component | ESP32 GPIO Pin | Function |
| --- | --- | --- |
| **DHT22 Sensor** | `GPIO 23` | Ambient Air Temperature (°C) & Humidity (%) |
| **DS18B20 Waterproof Probe** | `GPIO 4` | Sub-Surface Pool Water Temperature (°C) |
| **SSD1306 OLED (SCL / SDA)** | `GPIO 22 / GPIO 21` | Local Display (`EcoPool-AI Live`, Pool Temp, Heater Status) |
| **5V Heater Relay Module** | `GPIO 5` | Physical Contactor Switch (`LOW` = ON, `HIGH` = OFF) |
| **Green Indicator LED** | `GPIO 18` | Active Heating Indicator (`HEATER ON`) |
| **Red Indicator LED** | `GPIO 19` | AI Auto-Shutoff / Standby Indicator (`HEATER OFF`) |

## 📡 Core API Reference

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/api/energy-optimization/live-sensors` | Streams cached real-time ESP32 telemetry (`ambientTemp`, `humidity`, `currentPoolTemp`) and active `hardwareControlMode`. |
| `POST` | `/api/energy-optimization/check` | Executes 20-minute ML thermal prediction, calculates `mlStopPoint` and CEB savings, evaluates `33.0°C–35.0°C` hysteresis, and publishes `"ON"`/`"OFF"` to ESP32 via MQTT. |
| `POST` | `/api/energy-optimization/override` | Dispatches manual or automated stop-point override commands (`"ON"`, `"OFF"`, `"AUTO"`) to MQTT topic `ecopool/umi/control`. |
| `GET` | `/api/health` | Verifies overall Express backend server status and timestamp. |
