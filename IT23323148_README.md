## 📖 Executive Summary
Traditional commercial, resort, and municipal swimming pool management relies heavily on static, fixed-interval operational routines. Filtration pumps typically run on rigid mechanical timers regardless of swimmer bather load, leading to significant electrical waste, premature pump motor degradation, and sub-optimal water sanitization. Simultaneously, facility managers struggle with manual lifeguard and operator scheduling, often overstaffing during tranquil periods or endangering swimmer safety through understaffing during sudden bather surges.

The **Predictive Resource Orchestrator** is an intelligent, end-to-end cyber-physical system designed to transform swimming pool facility management from a reactive, manual paradigm to a predictive, autonomous system. By integrating:
1. **Edge IoT Gate Sensors (ESP32)** measuring directional ingress/egress in real time,
2. **Machine Learning Occupancy Forecasting (Random Forest Regressor)** anticipating swimmer volume 6 hours in advance based on temporal patterns, calendar holidays, and meteorological forecasts (Open-Meteo),
3. **Adaptive 4-Tier Filtration Actuation (ESP32 Relay)** regulating pump cycles between Eco, Standard, Boost, and Peak modes, and
4. **Intelligent Staff Scheduling & Automated Dispatch (Meta WhatsApp Cloud API)** issuing instant duty alerts and logging staff acceptance/rejection in real time,

the component delivers substantial reductions in facility energy consumption, ensures regulatory swimmer safety ratios, and extends electro-mechanical equipment longevity.

## 🚀 Key Features

### 1. Real-Time Telemetry & Occupancy Tracking
- Ingests high-frequency entry and exit events from an ESP32 edge gateway over MQTT (HiveMQ broker).
- Continuously calculates net pool occupancy and synchronizes with PostgreSQL (Supabase).
- Audits ingress/egress timestamps in 12-hour local time (Asia/Colombo timezone).

### 2. 6-Hour Forward-Looking ML Occupancy Forecasting
- Deploys an optimized Scikit-learn Random Forest regression pipeline served via FastAPI.
- Analyzes 6 multidimensional operational and environmental features:
  - `hour`: Time of day (0–23).
  - `day`: Day of week (Monday through Sunday).
  - `weekend`: Binary flag (Saturday/Sunday).
  - `holiday`: Sri Lanka statutory/public holiday status (`date-holidays` integration).
  - `rain`: Binary precipitation flag.
  - `weather`: Categorical condition (`Sunny`, `Cloudy`, `Rainy`) fetched dynamically from Open-Meteo.
- Returns hourly predicted swimmer load, demand level classification (`Low`, `Moderate`, `High`, `Peak`), and recommended operational actions.

### 3. Dynamic 4-Tier Adaptive Filtration Regulation
- Replaces uncalibrated 24/7 pump cycles with dynamic demand-based regulation:
  - **Mode 1 — Eco Filtration:** Low speed; activates during off-peak, night hours, or low bather load for maximum energy conservation.
  - **Mode 2 — Standard Filtration:** Medium speed; standard baseline turnover for normal operational traffic.
  - **Mode 3 — Boost Filtration:** High speed; accelerated turnover for elevated bather loads.
  - **Mode 4 — Peak Filtration:** Maximum speed; full-capacity turnover triggered during intense swimming traffic or bather saturation.
- Features bi-directional MQTT control with manual safety overrides via an interactive UI modal.

### 4. Automated Lifeguard Roster Allocation & WhatsApp Dispatch
- Calculates required on-duty lifeguards dynamically based on facility policy (e.g., $\lceil\text{occupancy} / \text{ratio}\rceil$).
- Automatically maps available certified personnel from the staff roster.
- Sends shift assignment alerts directly to staff smartphones via **Meta WhatsApp Cloud API**.
- Two-way webhook captures staff responses (`CONFIRM` / `REJECT`), updating assignment badges in real time.
- Integrated two-way WhatsApp live console in the dashboard to converse with staff and customers.

### 5. Automated Model Drift Monitoring & Retraining
- Continuously records actual sensor-derived occupancy against previous predictions.
- Retraining engine triggers automatic retraining whenever 48+ new ground-truth hourly records accumulate or when cumulative Mean Absolute Error exceeds configured thresholds.

## 📊 Database Schema Overview

The component utilizes 8 normalized tables hosted on PostgreSQL / Supabase:

| Table Name | Description | Key Attributes |
|---|---|---|
| `person_traffic_events` | High-frequency gate entry/exit telemetry | `id`, `event_type`, `occupancy_after`, `sensor_id`, `time_12h`, `recorded_at` |
| `hourly_pool_occupancy` | Ground-truth hourly dataset for model retraining | `target_hour`, `hour`, `day`, `weekend`, `holiday`, `rain`, `weather`, `actual_swimmers` |
| `pool_predictions` | 6-hour forward-looking inference cache | `forecast_time`, `target_hour`, `predicted_swimmers`, `demand_level`, `recommended_filtration_mode` |
| `filtration_events` | Actuation telemetry & pump override audit logs | `mode_number`, `mode_name`, `flow_rate_lpm`, `trigger_source`, `recorded_at` |
| `pool_orchestrator_settings`| Dynamic facility rules, capacities, and ratios | `facility_name`, `max_capacity`, `swimmer_to_lifeguard_ratio`, `mode_thresholds` |
| `facility_staff` | Staff roster with roles & phone numbers | `name`, `role`, `phone_number`, `status`, `certifications` |
| `staff_assignments` | Shift duty allocations & dispatch logs | `staff_id`, `shift_date`, `shift_hour`, `status` (`pending`, `confirmed`, `rejected`) |
| `whatsapp_messages` | Full audit trail of two-way WhatsApp messages | `phone_number`, `sender_type`, `direction`, `message_text`, `status`, `created_at` |

## 🛠 Technology Stack

### Frontend Client
- **Framework:** React 18 with Vite
- **Styling:** Custom CSS3 with responsive Glassmorphic design and CSS Grid / Flexbox
- **Icons:** FontAwesome 6 & Inline SVGs
- **API Communication:** Axios with automated 20-second background polling

### Backend Server
- **Runtime:** Node.js (v18+)
- **Framework:** Express.js
- **Database Client:** `pg` (PostgreSQL connection pooler compatible with Supabase)
- **Messaging / Telemetry:** MQTT.js (`mqtt://broker.hivemq.com:1883`)
- **Calendar & Holidays:** `date-holidays` (Sri Lanka locale `LK`)
- **External Communications:** Meta WhatsApp Cloud API via Axios

### Machine Learning Service
- **Runtime:** Python 3.10+ / 3.12
- **Framework:** FastAPI with Pydantic schema validation & Uvicorn ASGI server
- **ML Engine:** Scikit-Learn (Random Forest Regressor Pipeline)
- **Serialization:** Joblib
- **Data Manipulation:** Pandas & NumPy

### Edge IoT Hardware
- **Processor:** ESP32 Dual-Core 240MHz Microcontroller
- **Sensors:** Directional IR / Ultrasonic beam sensors for pedestrian entry/exit tracking
- **Actuators:** 4-Channel 5V Relay board controlling multi-speed filtration pump contactors
- **Firmware Protocol:** MQTT client publishing JSON telemetry payloads

## 🚦 Installation & Execution Guide

### 1. Database Setup
1. Log in to your Supabase project or PostgreSQL instance.
2. Open the SQL Editor and execute the script located at:
   `server/src/pool-orchestrator/schema.sql`.

### 2. Machine Learning Service (FastAPI)
```bash
# Navigate to the ML service directory
cd ml-service/pool-orchestrator

# Create and activate a Python virtual environment
python -m venv .venv

# Windows activation:
.\.venv\Scripts\activate

# Install required dependencies
pip install -r requirements.txt

# Run the FastAPI server on port 8000
uvicorn poolOrchestratorApp:app --host 127.0.0.1 --port 8000 --reload
```
*Health check URL: `http://127.0.0.1:8000/health`*

### 3. Backend API Server (Node.js & Express)
```bash
# Navigate to server directory
cd server

# Install npm dependencies
npm install

# Start the Express backend (runs on port 5001)
npm start
```
*API Health check: `http://localhost:5001/api/pool-orchestrator/health`*

### 4. Frontend Web Application (React & Vite)
```bash
# Navigate to frontend directory
cd frontend

# Install dependencies
npm install

# Start Vite development server
npm run dev
```
*Application Dashboard: `http://localhost:5173`*
